# 🏨 نصب کامل — هتل تا ۳۰۰ اتاق

راهنمای استقرار Hotel Media در مقیاس واقعی: انتخاب سیستم‌عامل، سخت‌افزار،
شبکه، نصب سرور، و راه‌اندازی ۳۰۰ تلویزیون.

---

## ۱) کدام سیستم‌عامل؟ — **Ubuntu Server LTS**

برای ۳۰۰ اتاق **لینوکس پایدارتر است**، و این یک ترجیح سلیقه‌ای نیست؛ دلیل فنی دارد:

### مشکل نصب ویندوزی فعلی

نصب‌کننده‌ی ویندوزی (`Setup-HotelMedia.exe`) وب‌سرور را با `php -S` بالا می‌آورد.
این وب‌سرور **تک‌نخی** است و در هر لحظه فقط **یک** درخواست را پردازش می‌کند.

اندازه‌گیری واقعی روی همین پروژه (لپ‌تاپ سریع، بدون بار دیگر):

| مسیر | توان عملیاتی | تأخیر میانه |
|------|--------------|-------------|
| `/tv` (صفحه ساده) | ۵۰ درخواست/ثانیه | ۳۹۸ ms |
| `/api/v1/portal/{code}` (چند کوئری) | **۳۷ درخواست/ثانیه** | **۵۴۶ ms** |

بار واقعی ۳۰۰ اتاق:

```
۳۰۰ تلویزیون ÷ ۳۰ ثانیه heartbeat  =  ۱۰ درخواست/ثانیه  (پایه)
+ بارگذاری پورتال، EPG، ویجت‌های زنده
+ پخش ویدیو و VOD
```

عدد پایه در محدوده کار می‌کند، ولی **حاشیه‌ای نمی‌ماند**. و یک مشکل بدتر:
در `php -S` یک دانلود ویدیوی ۵۰۰ مگابایتی، **کل سرور را تا پایان دانلود قفل
می‌کند** — چون همان تک‌نخ مشغول ارسال فایل است. در هتلی که چند مهمان همزمان
فیلم می‌بینند، این یعنی قطعی سرویس برای بقیه.

### راه‌حل: nginx + PHP-FPM

| | `php -S` (ویندوز فعلی) | nginx + PHP-FPM (لینوکس) |
|---|---|---|
| پردازش موازی | ۱ درخواست | ۳۲ worker همزمان |
| سرو ویدیو | از داخل PHP، قفل‌کننده | مستقیم با `sendfile`، بدون PHP |
| ظرفیت تخمینی | ~۴۰ req/s | ~۱۰۰۰ req/s |
| رفتار در اوج | صف و timeout | صف‌بندی سالم |
| مصرف رم | کم ولی بی‌فایده | ~۲ گیگ برای ۳۲ worker |

### جمع‌بندی انتخاب

| اندازه هتل | پیشنهاد |
|-----------|---------|
| تا ۳۰ اتاق | نصب‌کننده‌ی ویندوزی کافی است |
| ۳۰ تا ۱۰۰ اتاق | ویندوز + IIS/nginx و PHP-FPM، یا لینوکس |
| **۱۰۰ تا ۳۰۰+ اتاق** | **Ubuntu Server 22.04/24.04 LTS** ← این راهنما |

> اگر سیاست IT هتل فقط ویندوز را اجازه می‌دهد: ویندوز سرور با **nginx +
> php-cgi pool** یا **IIS + FastCGI** هم کار می‌کند. چیزی که نباید بماند،
> `php -S` است.

## ۲) سخت‌افزار

### سرور مرکزی

| بخش | حداقل | پیشنهادی برای ۳۰۰ اتاق |
|-----|-------|------------------------|
| پردازنده | ۴ هسته | **۸ هسته** |
| رم | ۸ گیگ | **۱۶ گیگ** |
| دیسک سیستم | ۵۰ گیگ SSD | **۱۰۰ گیگ SSD (NVMe)** |
| دیسک محتوا | ۵۰۰ گیگ | **۲ ترابایت** (VOD + ضبط) |
| شبکه | ۱ گیگابیت | **۱۰ گیگابیت** به سوییچ مرکزی |

**درباره‌ی دیسک:** دیتابیس روی SSD باشد. ویدیو می‌تواند روی HDD باشد، چون
با `sendfile` سرو می‌شود و تنگنای آن پهنای‌باند است نه IOPS.

**اگر ترنسکد زنده دارید** (کانال RTSP → HLS): هر کانال حدود یک هسته مصرف
می‌کند. برای ۱۰ کانال ترنسکد، ۸ هسته‌ی دیگر یا یک سرور جدا در نظر بگیرید.

### شبکه

```
                    ┌─────────────────┐
     اینترنت ───────┤  فایروال / روتر  │
                    └────────┬────────┘
                             │
                    ┌────────┴────────┐
                    │  سوییچ مرکزی     │  ۱۰G
                    │  (VLAN 20: TV)   │
                    └────────┬────────┘
             ┌───────────────┼───────────────┐
             │               │               │
        ┌────┴────┐     ┌────┴────┐     ┌────┴─────┐
        │ سرور     │     │ سوییچ    │     │ TVHeadend│
        │Hotel Media│    │ طبقه ۱   │     │ (ماهواره)│
        └─────────┘     └────┬────┘     └──────────┘
                             │ ۱G
                   ┌─────────┼─────────┐
                  TV        TV        TV …
```

**نکات شبکه که در عمل مهم‌اند:**

- تلویزیون‌ها در **VLAN جدا** از شبکه‌ی مهمان و اداری باشند
- سرور باید IP **ثابت** داشته باشد — آدرس پورتال در منوی تلویزیون‌ها ثابت وارد می‌شود
- اگر VLAN تلویزیون اینترنت ندارد، مشکلی نیست: پلیر همه‌ی فایل‌هایش
  (فونت، آیکون، `hls.js`) را از سرور خودتان می‌گیرد
- ولی اگر **ویجت آب‌وهوا / نرخ ارز / اوقات شرعی** می‌خواهید، **سرور** باید
  به اینترنت دسترسی داشته باشد (نه تلویزیون‌ها)
- پهنای‌باند پخش: هر تلویزیون در پخش HD حدود ۵ تا ۸ مگابیت — ۱۰۰ تلویزیون
  همزمان یعنی حدود ۸۰۰ مگابیت. برای همین سوییچ مرکزی ۱۰ گیگ توصیه می‌شود.

## ۳) نصب سرور

### پیش‌نیاز

Ubuntu Server 22.04 یا 24.04 LTS، نصب تازه، با دسترسی sudo.

### اجرا

```bash
git clone https://github.com/kish210/hotel-media.git
cd hotel-media
sudo bash deploy/install-production.sh
```

اسکریپت به‌صورت خودکار:

1. سخت‌افزار را بررسی و درباره‌ی کمبود هشدار می‌دهد
2. nginx، PHP 8.3-FPM، MariaDB، ffmpeg و Composer را نصب می‌کند
3. دیتابیس و کاربر با **رمز تصادفی** می‌سازد
4. MariaDB را برای بار ۳۰۰ اتاق تنظیم می‌کند
5. `.env` با کلیدهای تازه می‌سازد
6. همه‌ی migration ها را اجرا می‌کند
7. **تعداد worker را از روی رم واقعی سرور** محاسبه می‌کند
8. سرویس WebSocket و کارهای زمان‌بندی‌شده را ثبت می‌کند
9. فایروال را باز می‌کند و `install.php` را غیرفعال می‌کند

### متغیرهای دلخواه

```bash
sudo APP_DIR=/srv/hotel-media DB_NAME=hotel PHP_VER=8.3 \
     bash deploy/install-production.sh
```

### بعد از نصب — سه کار واجب

```bash
# ۱) رمز ادمین را عوض کنید (اولین ورود به پنل)

# ۲) پشتیبان‌گیری خودکار دیتابیس
sudo tee /etc/cron.d/hotel-media-backup <<'EOF'
0 2 * * * root mysqldump --single-transaction hotel_media \
  | gzip > /var/backups/hotel-media-$(date +\%F).sql.gz
0 3 * * * root find /var/backups -name 'hotel-media-*.sql.gz' -mtime +14 -delete
EOF
sudo mkdir -p /var/backups

# ۳) HTTPS (اگر دامنه دارید)
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d tv.yourhotel.com
```

## ۴) راه‌اندازی ۳۰۰ تلویزیون

### مرحله ۱ — ساخت توکن ثبت

پنل ← **مدیریت تلویزیون‌ها** ← **توکن ثبت** ← توکن جدید

- عنوان: مثلاً «نصب مهر ۱۴۰۴ — طبقه ۱ تا ۵»
- منوی IPTV پیش‌فرض را انتخاب کنید
- **تایید خودکار** را روشن بگذارید تا ۳۰۰ دستگاه یکی‌یکی تایید نشوند

### مرحله ۲ — وارد کردن آدرس در تلویزیون‌ها

آدرس برای **همه‌ی تلویزیون‌ها یکسان** است:

```
http://<IP سرور>/tv
```

هر تلویزیون خودش را با MAC می‌شناساند و کد اختصاصی می‌گیرد.

#### LG — تلویزیون هتلی webOS

1. دکمه‌ی **MENU** را نگه دارید تا منو محو شود و اطلاعات کانال بیاید، رها کنید
2. بلافاصله **1105** بزنید و **OK** — منوی نصب باز می‌شود
3. **Manual Pro:Centric**:
   - `Pro:Centric Mode` → **HTML**
   - `Media Type` → **IP**
   - `IP Address` → IP سرور
   - `Port` → **80**
4. ذخیره و ریبوت

> با منوی **994** می‌توانید آدرس‌های ثبت‌شده را بررسی کنید.

#### Samsung — تلویزیون هتلی Tizen

1. روی ریموت سریع بزنید: **MUTE → 1 → 1 → 9 → ENTER**
   (توالی باید ظرف ۲ تا ۳ ثانیه کامل شود)
2. `Hospitality Mode` → **ON**
3. `SI Vendor` → **URL Launcher**
4. `URL Launcher Setting` → آدرس بالا
5. ذخیره و ریبوت

#### Android TV

1. فایل APK را از پنل ← **به‌روزرسانی اپ** نصب کنید
2. در اولین اجرا آدرس سرور را وارد کنید

### مرحله ۳ — تخصیص اتاق

بعد از ثبت، در پنل ← **مدیریت تلویزیون‌ها** هر دستگاه را به اتاقش وصل کنید.
دستگاه‌ها بر اساس MAC و مدل قابل تشخیص‌اند.

> **نکته‌ی عملی:** هنگام نصب، شماره اتاق و MAC هر تلویزیون را روی کاغذ
> یادداشت کنید. تخصیص ۳۰۰ اتاق بدون این فهرست، ساعت‌ها طول می‌کشد.

## ۵) اندازه‌گذاری و تنظیم

### فاصله‌ی heartbeat

بیشترین بار ثابت سیستم، همین است. در `.env`:

```ini
PLAYER_SYNC_INTERVAL=30    # ثانیه
```

| تعداد اتاق | مقدار پیشنهادی | بار حاصل |
|-----------|----------------|---------|
| تا ۵۰ | ۱۵ | ۳ req/s |
| ۵۰ تا ۱۵۰ | ۳۰ | ۵ req/s |
| **۱۵۰ تا ۳۰۰** | **۳۰ تا ۶۰** | **۵ تا ۱۰ req/s** |
| بیش از ۳۰۰ | ۶۰ | — |

تلویزیون‌ها این مقدار را از سرور می‌خوانند؛ نیازی به تغییر چیزی روی دستگاه‌ها نیست.

### تعداد worker

اسکریپت نصب خودکار حساب می‌کند (`رم ÷ ۶۰`)، ولی دستی هم می‌شود:

```bash
sudo nano /etc/php/8.3/fpm/pool.d/hotel-media.conf
# pm.max_children = 32
sudo systemctl reload php8.3-fpm
```

### پایش سلامت

```bash
# کوئری‌های کند — اولین جایی که باید نگاه کنید
tail -f /var/log/php-fpm/hotel-media.slow.log

# آیا worker ها کم آمده‌اند؟
grep "server reached pm.max_children" /var/log/php-fpm/hotel-media.error.log

# خطاهای وب
tail -f /var/log/nginx/hotel-media.error.log

# وضعیت سرویس‌ها
systemctl status nginx php8.3-fpm mariadb hotel-media-ws
```

اگر پیام `reached pm.max_children` دیدید، یعنی `pm.max_children` کم است —
افزایش دهید (با توجه به رم موجود).

## ۹) پخش زنده با Multicast — واجب برای ۳۰۰ اتاق

### عددی که تصمیم را می‌گیرد

با HTTP/HLS هر تلویزیون یک جریان **جدا** می‌گیرد:

```
۳۰۰ اتاق × ۸ Mbps  =  ۲٬۴۰۰ Mbps  (۲.۴ گیگابیت)
```

با multicast، هر کانال **یک بار** روی شبکه پخش می‌شود و سوییچ با IGMP
snooping فقط به پورت‌هایی که درخواست کرده‌اند تحویلش می‌دهد:

```
۳ کانال × ۸ Mbps  =  ۲۴ Mbps   ← مستقل از تعداد اتاق
```

**۹۹ درصد کاهش بار شبکه.** برای هتل بزرگ این تفاوت بین «کار می‌کند» و
«کانال‌ها می‌پرند» است.

### محدودیتی که باید بدانید

**‏HTML5 نمی‌تواند UDP multicast بخواند.** تگ `<video>` در مرورگر — از جمله
موتور webOS و Tizen — فقط HTTP، HLS و DASH می‌فهمد. پس معماری درست:

| مسیر | چه کسی پخش می‌کند | بار سرور |
|------|-------------------|----------|
| **تیونر خود تلویزیون** | LG و Samsung هتلی از فهرست کانال IP | **صفر** ✅ |
| **اپ بومی Android TV** | ExoPlayer با سوکت UDP | **صفر** ✅ |
| **پورتال HTML5** | از طریق udpxy (multicast → HTTP) | unicast ⚠️ |

**نتیجه‌ی عملی:** پخش زنده را به تیونر تلویزیون بسپارید و پورتال ما را برای
منو، EPG، خدمات و صورتحساب نگه دارید. udpxy فقط برای چند دستگاه استثنا.

> `via: "tv_tuner"` در پاسخ پورتال یعنی همین: کانال فقط از تیونر خود
> تلویزیون قابل دیدن است، نه از داخل پورتال.

### راه‌اندازی

**۱) تولید جریان multicast**

TVHeadend خودش multicast نمی‌دهد؛ خروجی HTTP آن را تبدیل کنید:

```bash
# برای هر کانال یک سرویس systemd
ffmpeg -i "http://tvh:9981/stream/channel/<uuid>?profile=pass" \
       -c copy -f mpegts "udp://239.1.1.10:5000?pkt_size=1316&ttl=4"
```

یا از `dvblast` که سبک‌تر است و مستقیم از کارت DVB می‌خواند.

**۲) تخصیص آدرس در پنل**

پنل ← کانال‌های IPTV ← multicast ← **تخصیص آدرس**. سیستم به هر کانال یک
گروه از بازه‌ی `239.x.x.x` می‌دهد (پورت با گام ۲ چون RTP پورت زوج می‌خواهد).
اجرای دوباره آدرس‌های موجود را دست نمی‌زند تا فهرست کانال تلویزیون‌ها به‌هم نریزد.

**۳) گرفتن فهرست کانال**

```
GET /api/v1/multicast/playlist.m3u?mode=multicast
```

این فایل را در تلویزیون‌های هتلی وارد کنید (LG و Samsung فهرست کانال IP را
از M3U می‌خوانند). حالت `mode=udpxy` همان فهرست را با آدرس HTTP می‌دهد.

**۴) udpxy برای کلاینت‌های HTML5** (اختیاری)

```bash
sudo apt install udpxy
sudo udpxy -p 4022 -m eth0 -a 0.0.0.0
```

سپس آدرس `http://<IP سرور>:4022` را در تنظیمات multicast پنل وارد کنید.

### تنظیم شبکه — بدون این، multicast شبکه را می‌خواباند

| تنظیم | کجا | چرا |
|-------|-----|-----|
| **IGMP Snooping** | همه‌ی سوییچ‌ها | بدون آن، multicast مثل broadcast به همه‌ی پورت‌ها می‌رود و شبکه را پر می‌کند |
| **IGMP Querier** | فقط **یک** سوییچ، نزدیک‌ترین به منبع | بیش از یکی باعث تداخل و قطعی می‌شود |
| **VLAN جدا** | شبکه‌ی تلویزیون‌ها | شبکه‌ی مهمان و اداری نباید ترافیک TV ببینند |
| **TTL = 4** | تنظیمات پنل | جریان از شبکه‌ی داخلی هتل بیرون نرود |
