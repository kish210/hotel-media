# مهاجرت از سیستم قدیمی (VINAK / MMS)

سیستم قدیمی هتل (بر پایهٔ `mmk_v2_200310`، پنل PHP `opt/sms/www`) داده‌اش را در پوشهٔ `conf`
نگه می‌داشت. این سند می‌گوید چه چیزی وارد می‌شود، چه چیزی نمی‌شود، و چرا.

## ۱) منبع

پوشه‌ای که `channels.json` دارد — خودش یا داخل `backups/<تاریخ>/conf`. اگر ریشهٔ backups بدهید،
**جدیدترین** `channels.json` انتخاب می‌شود: پشتیبان‌های قدیمی هم همان‌جا هستند و ورود دادهٔ کهنه
یعنی از دست دادن کانال‌هایی که بعدا اضافه شده‌اند.

| فایل | چه می‌شود |
|---|---|
| `channels.json` → `dvb[]` | هر کانال یک ردیف `iptv_channels` با `legacy_ref = DVBT<id>:<sid>` |
| `channels.json` → `outputs[]` | آدرس multicast از `net_multicast` ساخته می‌شود (`udp://@239.2.1.x:3200`) |
| `users.json` (۳۲۸ ردیف) | `iptv_rooms` — شمارهٔ اتاق، زبان، IP قدیمی در `legacy_ip` |
| `configs.json` | `legacy_settings` (کلید/مقدار) + یک ردیف `pms_integrations` اگر PMS داشت |
| `assets/chan_logo` | کپی در `public/assets/channel-logos/` (بدون بازنویسی موجودها) |
| `user_data_*.sqlite3` | فقط **کاتالوگ** به `storage/legacy/vod-catalog.csv` |

## ۲) سه تصمیمی که باید بدانید

**الف) ادغام، نه جایگزینی.** هر ردیف با `legacy_ref` (یا نام/شمارهٔ اتاق) پیدا و به‌روز می‌شود.
اجرای دوبارهٔ مهاجرت بی‌خطر است و تنظیمات دستی کانال را پاک نمی‌کند.

**ب) فایل‌های ویدیو وارد نمی‌شوند.** ردیف‌های VOD به فایل‌هایی روی دیسک همان سرور اشاره می‌کردند
که همراه پشتیبان نیستند. واردکردنشان یعنی هزاران کارت فیلم که پخش نمی‌شود. کاتالوگ CSV می‌شود تا
اپراتور بداند چه داشته و خودش آپلود کند (`/admin/vod`).

**ج) وضعیت اتاق دست نمی‌خورد.** اتاقی که الان مهمان دارد با مهاجرت «آزاد» نمی‌شود.

## ۳) اجرا

از پنل: **مدیریت → مهاجرت از سیستم قدیمی** (فقط `super_admin`). دکمهٔ «پیش‌نمایش» هیچ‌چیز
نمی‌نویسد و فقط تعدادها را نشان می‌دهد؛ «اجرای مهاجرت» می‌نویسد.

از خط فرمان:

```bash
php artisan legacy:import /path/to/conf --logos          # ادغام
php artisan legacy:import /path/to/conf --dry                      # فقط شمارش
php artisan legacy:import /path/to/conf --logos --teletext
```

## ۴) بعد از مهاجرت

   `GB_Teletext=false` داشت، تله‌تکست خاموش می‌ماند (همان قرارداد).
1. **کانال‌ها**: آدرس multicast وارد شده، ولی تلویزیون‌ها هنوز از TVHeadend پخش می‌کنند.
   در `/admin/iptv/tvheadend` → «همگام‌سازی کانال» کانال‌های واقعی را بیاورید و تکراری‌ها را
   (`legacy_ref`) حذف یا غیرفعال کنید.
2. **PMS**: ردیف `pms_integrations` با `pms_type='asa'` ساخته می‌شود. رمز قدیمی منتقل شده —
   **عوضش کنید** و از `/admin/iptv/rooms` دکمهٔ آزمایش اتصال را بزنید.
3. **رمز ادمین قدیمی منتقل نمی‌شود** (هش MD5 است و با bcrypt هتل مدیا نمی‌خواند). کاربر جدید
   بسازید: `php artisan user:create`.

## ۵) بازگشت

مهاجرت ردیف اضافه/به‌روز می‌کند و چیزی حذف نمی‌کند، پس بازگشت لازم نیست. اگر خواستید همهٔ
کانال‌های واردشده را بردارید:

```sql
DELETE FROM iptv_channels WHERE legacy_ref LIKE 'DVBT%';
```
