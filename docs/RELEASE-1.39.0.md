# نسخهٔ ۱.۳۹.۰ — دادهٔ نمونه و مستند کانال

## چه شد

روی نصب آزمایشی، دادهٔ نمونه از مسیرهای واقعی پنل ساخته شد و مستند گردید:
سه **کانال HLS** در گروه «نمونه»، رسانه و پلی‌لیست لابی، زمان‌بندی صفحهٔ
`SCR001` و پیام خوش‌آمد.

سند کامل: [`docs/SAMPLE-DATA.md`](SAMPLE-DATA.md).

## کانال‌های نمونه

| نام | گروه | پروتکل | آدرس |
|---|---|---|---|
| کانال نمونه — سرگرمی | نمونه | hls | `devstreaming-cdn.apple.com/.../bipbop_16x9_variant.m3u8` |
| کانال نمونه — سینما | نمونه | hls | `demo.unified-streaming.com/.../tears-of-steel.ism/.m3u8` |
| کانال نمونه — آموزشی | نمونه | hls | `devstreaming-cdn.apple.com/.../img_bipbop_adv_example_fmp4/master.m3u8` |

هر سه آدرس پیش از ثبت با `curl` روی **خود سرور** بررسی شدند (۲۰۰). نسخهٔ
اول از `test-streams.mux.dev` استفاده می‌کرد که روی این سرور `000` می‌داد —
کانالی که آدرسش از سرور باز نشود روی تلویزیون هم پخش نمی‌شود، پس آدرس عوض شد.

### باگی که تست پیدا کرد: ZIP فقط روی ویندوز باز می‌شد

`Get-ChildItem` مسیر نسبی را می‌داد ولی `ZipFile::CreateFromDirectory` روی
PowerShell 5.1 (دات‌نت فریم‌ورک) نام ورودی‌ها را با **بک‌اسلش** می‌نویسد:
`docs\API.md`. روی لینوکس چنین ZIPی به یک پوشهٔ تخت باز می‌شود — همهٔ
فایل‌ها با نام `docs\API.md` کنار هم، بی `app/` و بی `config/` — و نصب
شکست می‌خورد. اسکریپت حالا ورودی‌ها را خودش با `/` می‌نویسد.

### آزمون بسته

| آزمون | نتیجه |
|---|---|
| استخراج ZIP روی سرور آزمایشی (Ubuntu) | درخت درست: `app/ config/ docs/ public/ resources/ routes/ scripts/` |
| `php -l` روی همهٔ فایل‌های PHP بسته | ۲۶۹ فایل، **۰ خطا** |
| `VERSION` و `docs/SAMPLE-DATA.md` داخل بسته | موجود، `1.39.0` |
| ساختار ISO (El Torito، `casper/vmlinuz`، `casper/initrd`) | سالم |
| `user-data` داخل ISO | YAML معتبر، `version: 1`، کاربر `hotel`، ۸ `late-commands` که بسته را از `/cdrom` می‌خوانند |
| بستهٔ برنامه داخل ISO | ۲۰۹۳ فایل، `VERSION` = `1.39.0`، `vendor/` همراه، بی `.env` |
| پنل و پورتال روی نصب آزمایشی | `/login` ۲۰۰، `/admin/dashboard` ۳۰۲، `/api/v1/portal/SCR001` ۲۰۰ با ۳ کانال `playable=true` |

ISO از سقف ۲ گیگابایتی ضمیمه‌های گیت‌هاب بزرگ‌تر است، پس فقط ZIP ضمیمه شد؛
ISO از `deploy/iso/build-iso.py` بازساختنی است.
