# نسخهٔ ۱.۳۸.۰ — تنظیم دستیار هوشمند از خود پنل

## چرا این نسخه

بخش «دستیار هوشمند» و «OpenHand» روی نصب واقعی هتل هیچ کاری نمی‌کردند و پیام
«تنظیم نشده» می‌دادند. علت، نبودِ سه کلید در `.env` بود:

```
AI_ENABLED=true
AI_BASE_URL=https://<gateway>/v1
AI_API_KEY=...
AI_MODEL=<model>
```

تا پیش از این نسخه، تنها راه گذاشتن این‌ها ویرایش دستی `.env` روی SSH بود —
یعنی اپراتور پنل هیچ راهی برای فعال‌کردن دستیار نداشت.

## چه چیزی عوض شد

- صفحهٔ `/admin/system/ai` یک فرم «اتصال» دارد: آدرس سرویس، کلید API، نام مدل و
  چک‌باکس فعال‌سازی. مقادیر در `.env` نوشته می‌شوند (`AiController::saveConfig`).
- کلید هرگز به مرورگر برنمی‌گردد؛ فیلد آن همیشه خالی است و فقط ۴ کاراکتر آخر آن
  به‌عنوان راهنما نمایش داده می‌شود.
- اگر کلید از قبل ذخیره شده باشد و اپراتور فیلد را خالی بگذارد، کلید قبلی دست
  نمی‌خورد.
- اعتبارسنجی: آدرس باید `http(s)://…` باشد، کلید ۸ تا ۲۰۰ نویسهٔ چاپ‌پذیر بدون
  فاصله، نام مدل با همان قاعدهٔ قبلی (`setModel`).
- دستیار فقط وقتی `AI_ENABLED=true` می‌شود که آدرس و کلید (تازه یا قبلی) موجود
  باشد؛ وگرنه ذخیره می‌شود ولی خاموش می‌ماند و پیام روشن می‌دهد.

## مسیر فایل‌ها

| فایل | تغییر |
|---|---|
| `app/Controllers/Web/AiController.php` | `saveConfig()` و `envPut()` |
| `routes/web.php` | `POST /admin/system/ai/config` |
| `resources/views/admin/system/ai.php` | فرم اتصال + `saveConfig()` در JS |

## ارتقا

از پنل: **سیستم → به‌روزرسانی** (انتشار `v1.38.0` روی گیت‌هاب) یا
`git pull` روی سرور. مهاجرت دیتابیس ندارد.

پس از به‌روزرسانی، یک‌بار `/admin/system/ai` را باز کنید، آدرس و کلید را وارد
کنید و «ذخیرهٔ اتصال» را بزنید؛ بعد «دریافت فهرست مدل‌ها» و انتخاب مدل.
