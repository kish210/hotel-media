# سازگاری تلویزیون‌های هتل با پخش Signage

> این سند بر پایه‌ی اسکن واقعی سایت روی سرور تولید (`iptv-sama` / `172.16.100.29`)
> در ۱۴۰۵/۰۷/۰۵ نوشته شده. هدفِ فعلی فقط **signage** است؛ بخش IPTV و استفاده از
> کد Kamasystem برای فاز بعد است و در انتها آمده.
>
> هیچ چیزی روی سرور یا تلویزیون‌ها تغییر داده نشد — فقط شناسایی و تست خواندنی.

## ۱) توپولوژی شبکه‌ی تلویزیون‌ها

| مورد | مقدار |
|---|---|
| رنج تلویزیون‌ها (VLAN مهمان) | `172.33.0.0/20` |
| سرور signage/CMS ما | `172.16.100.29` (پورت‌فوروارد بیرونی `2.184.238.173:33622`) — رنجِ دیگری‌ست |
| سرور IPTV قدیمی (Kamasystem) | `172.33.0.2` و `172.33.0.100` (همان باکس، نام هتل: «پالاس») |
| gateway/router رنج تلویزیون | `172.33.0.1` |

**نکته‌ی حیاتی درباره‌ی پورت ۸۰۰۱ (و ۸۰۰۰/۸۰۰۲/۹۰۹۰):**
این پورت‌ها روی **همه‌ی** IP های رنج یک جواب یکسان می‌دهند — حتی IP هایی که اصلاً
دستگاهی ندارند و به ping جواب نمی‌دهند (`172.33.13.77` هم تست شد). یعنی روی router
یک redirect شفاف نشسته و همه را به باکس Kama می‌فرستد. پس **۸۰۰۱ ربطی به تلویزیون
ندارد** و برای شناسایی مدل بی‌فایده است؛ فقط پورت‌های واقعیِ خودِ تلویزیون
(`7676` / `9197` / `8080`) معتبرند.

## ۲) دو خانواده‌ی تلویزیون که کشف شد

روش شناسایی: UPnP device description خود تلویزیون
(`http://<ip>:7676/smp_7_` روی Orsay و `http://<ip>:9197/dmr` روی Tizen)،
که `modelName` و `sec:ProductCap` را بدون احراز هویت می‌دهد.

### خانواده A — سامسونگ Tizen هتلی (نسل ۲۰۱۸)
- **مدل:** `HA49J690`
- **امضا:** `Tizen, Y2018, WebURIPlayable, NavigateInPause, vdProductType=HTV`
  به‌همراه سریال کامل (مثل `060W3NNN300087H`) و MAC.
- **پورت‌های واقعی باز:** `9197` (UPnP MediaRenderer / DMR-1.50)، `8080` (HTTP با `Access-Control-Allow-Origin: *`).
- **IP ها (۱۵ عدد):** `0.230, 1.9, 3.7, 3.9, 3.13, 4.13, 4.18, 5.5, 5.9, 5.10, 5.13, 5.16, 6.10, 7.13, 7.16`

### خانواده B — سامسونگ Orsay/Maple (نسل ۲۰۱۳)
- **مدل:** `HG49AE690` (یک عدد `HG49EE690`)
- **امضا:** `ProductCap = Y2013`، `deviceType = MainTVServer2` — نسل پیش از Tizen.
- **پورت‌های واقعی باز:** `7676` (UPnP SEF/Orsay: `smp_2_ … smp_16_`)، `8080` (HTTP، CORS محدود به youtube.com).
- **نامِ friendlyName شماره‌ی اتاق است:** `[TV]1008`, `[TV]6013`, `[TV]10001`, `[TV]12011` …
- **IP ها (۱۷ عدد):** `0.188, 0.191, 0.236, 1.8, 1.11, 1.72, 1.73, 1.249, 2.10, 6.1, 6.5, 6.8, 6.13, 9.6, 9.13, 10.1`

> ۵ دستگاه (`1.4, 1.10, 2.6, 5.19, 10.20`) وسط اسکن خاموش/خواب شدند؛ از الگوی پورت،
> `1.10` خانواده A و بقیه خانواده B اند. باید موقع روشن‌بودن دوباره تأیید شوند.

**چرا این تفکیک مهم است:** موتور مرورگرِ دو خانواده کاملاً فرق دارد و همین سرنوشتِ
سازگاری signage را تعیین می‌کند (بخش ۴).

## ۳) نحوه‌ی ارتباط برای Signage

مدلِ ما **pull** است: تلویزیون یک URL ثابت (`http://172.16.100.29/tv`) را در
URL Launcher باز می‌کند؛ صفحه خودش را با توکن ثبت (`enrollment_tokens`) رجیستر
می‌کند، کد `TVxxxxx` می‌گیرد و از آن‌جا پلیر `/player/{code}` را می‌آورد
(بخش `bootstrap.php` و `TvBootstrapController`).

### راه‌اندازی روی خانواده A (Tizen 2018)
منوی هتلی سامسونگ: روی ریموت سریع بزن **MUTE → 1 → 1 → 9 → ENTER**
(کمتر از ۲–۳ ثانیه، وگرنه باز نمی‌شود).
1. `Hospitality Mode` → `ON`
2. بخش **URL Launcher Setting** (در بعضی مدل‌ها زیر `SI Vendor` یا `Server URL Setting`)
3. آدرس سرور ما: `http://172.16.100.29/tv`
4. `SI Vendor` → `URL Launcher` و ریبوت.

چون ProductCap این خانواده صریحاً `WebURIPlayable` دارد، URL Launcher روی آن
قابل‌اتکاست و پلیر HTML5 ما اجرا می‌شود.

### راه‌اندازی روی خانواده B (Orsay 2013)
همان منوی MUTE-1-1-9 را دارد، ولی روی نسل Orsay گزینه به‌جای «URL Launcher»
معمولاً **Hospitality → Solution/SI → «Samsung URL Launcher» یا «Custom»** است و
موتورِ صفحه، مرورگر قدیمی Maple است، نه Tizen WebEngine. آدرس یکسان است، اما
سازگاری صفحه تضمین‌شده نیست — بخش بعد.

## ۴) سازگاری کدِ فعلی و شکاف‌ها

پلیر signage سامسونگ ما: [`resources/views/player/profiles/samsung_tv.php`](../resources/views/player/profiles/samsung_tv.php)
و کمک‌تابع‌های مشترک: [`public/assets/js/tv-base.js`](../public/assets/js/tv-base.js).
پلیر عمداً ES5 است (بدون `const/let`، arrow، template literal، `fetch`، `Promise`)
و از `XMLHttpRequest` + `<img>` + `<video>` HTML5 استفاده می‌کند.

### خانواده A — Tizen 2018 ✅ سازگارِ کامل
- WebEngine مبتنی بر Chromium مدرن؛ `object-fit`, `classList`, HTML5 video، همه هست.
- `$WEBAPIS/webapis/webapis.js` و مسیر AVPlay در پروفایل موجود است (با fallback به `<video>`).
- multicast مستقیم: این نسل `udp://` / `rtp://` را خودش در `<video>` می‌خواند و بار سرور صفر می‌شود (کامنت داخل `play()` همین را می‌گوید).
- **اقدام لازم:** ندارد. همین حالا کار می‌کند.

### خانواده B — Orsay 2013 ⚠️ نیازمند پروفایل جدا
موتور Maple روی WebKit ~534/535 است. مشکلات مشخص با پلیر فعلی:

| قابلیتی که پلیر استفاده می‌کند | وضع روی Orsay 2013 | اثر |
|---|---|---|
| `object-fit: cover/contain` (روی img/video) | از WebKit ~537 آمده — **نیست** | تصویر/ویدیو کش‌آمده یا بریده |
| `<video>` با HLS/`.m3u8` native | نیست | فقط MP4 مستقیم مطمئن است |
| `udp://`/`rtp://` در `<video>` | نیست (کار AVPlay/pipeline بومی است) | multicast مستقیم پخش نمی‌شود |
| `webapis.js` / AVPlay | Orsay از SEF/Maple API استفاده می‌کند نه AVPlay | شاخه‌ی AVPlay بی‌اثر، به `<video>` می‌افتد |
| `classList` | روی 534 هست ولی مرزی؛ باید تست شود | احتمال کار، ولی ریسک |

**اقدام انجام‌شده (نسخه ۱.۹، برای signage روی خانواده B):**
1. ✅ پروفایل مجزا [`resources/views/player/profiles/orsay_tv.php`](../resources/views/player/profiles/orsay_tv.php) ساخته شد:
   - جای `object-fit` از `background-size:cover` روی یک `div` (تصویر) استفاده می‌شود.
   - فقط تصویر و ویدیوی **MP4/WebM مستقیم**؛ HLS/`m3u8` و `udp://`/`rtp://` صریحاً
     رد و رها می‌شوند تا صفحه سیاه نماند.
   - شاخه‌ی AVPlay و `webapis.js` حذف شد؛ فقط `<video>` ساده. بدون `classList`
     (سوییچ اسلاید با ست‌کردن مستقیم `opacity`).
2. ✅ در [`DeviceService`](../app/Services/DeviceService.php) پلتفرم `orsay` به
   `PLATFORMS`، به `CAPABILITIES` (فقط `refresh/message/open_url/clear_cache`)، به
   `detectPlatform()` (تشخیص با `maple`/`smarthub` **پیش از** `tizen`) و به
   `platformLabel()` اضافه شد.
3. ✅ انتخاب خودکار پروفایل در [`PlayerController`](../app/Controllers/Web/PlayerController.php):
   اگر `player_profile` دستی ست نشده باشد، بر اساس `screen.platform` انتخاب می‌شود
   (`orsay → orsay_tv`، `tizen → samsung_tv`، `webos → lg_tv`، `android → android_tv`).
   `orsay_tv` به whitelist پروفایل‌ها و به دراپ‌داون پنل (صفحه‌ی screen) و برچسب
   صفحه‌ی «دستگاه‌ها» هم اضافه شد.
4. ✅ `tv-compat-lint.js` روی پروفایل جدید اجرا شد — بدون هیچ ویژگی ناسازگار با
   Chromium 34/Maple.

> این‌ها فرضِ محافظه‌کارانه بر پایه‌ی موتور Maple اند و روی PHP 8.3 سرور lint شدند؛
> صحّت پخش هنوز باید روی یک دستگاه واقعیِ خانواده B (مثلاً `172.33.6.13 = [TV]6013`)
> تأیید شود — به‌خصوص رفتار `<video>` و `background-size:cover`.

> بدون یک دستگاه واقعیِ خانواده B برای تست، این‌ها فرضِ محافظه‌کارانه‌اند؛ صحّتشان
> باید روی یک اتاق (مثلاً `172.33.6.13 = [TV]6013`) تأیید شود. اسکن `object-fit` و
> `classList` را نمی‌شود از راه دور روی خود TV سنجید.

## ۵) کد Kamasystem — برای فاز IPTV (نه اکنون)

باکس `172.33.0.100` چند سرویس هم‌زمان دارد (همه از طریق redirect شفافِ router روی
کل رنج هم در دسترس‌اند):

| پورت | موتور | نقش |
|---|---|---|
| `80` | Apache | صفحه‌ی «Kamasystem IPTV Server» (فقط بنر) |
| `8000` | Apache/PHP | پنل پرسنل/پذیرش: `hotel/index1.php` (پذیرش، صندوق‌دار، چندزبانه) |
| `8002` | Apache/PHP | **پرتال مهمان IPTV** (Bootstrap/RTL) — بخش قابل‌استفاده برای ما |
| `9090` | **IIS / ASP.NET Web API (MVC 5.2)** | بک‌اند واقعی؛ نسخه `1405.0.0.1`، تاریخ انتشار 2025-02-25 |

**جریان پرتال مهمان (۸۰۰۲) که ارزش الگوبرداری دارد:**
```
index (انتخاب: «مقیم هتل» / «مهمان آزاد»)
  → check-info.php?check=1   (فرم: شماره اتاق + کد ملی)
      → POST ajaxer.php  action=check_passenger_room&na_num=&room_num=
          → موفق: categories.php (دسته‌بندی/کانال‌ها، سبد خرید، food-collection)
```
- احراز مهمان = **شماره اتاق + کد ملی** (نه رمز). این همان مدلی است که برای
  پورتال IPTV خودمان هم منطقی است و می‌شود در `PortalController` بازتولید کرد.
- لایه‌ی داده (کانال، اتاق، EPG) روی **۹۰۹۰/ASP.NET** است؛ مسیرها زیر `/api/`
  با مسیریابی Web API اند (۴۰۴ صریحِ «No HTTP resource was found …» می‌دهد). نام
  دقیق controllerها هنوز پیدا نشده — قدم بعدی: تطبیق با پرتال ۸۰۰۲ برای دیدن این‌که
  `categories.php`/`ajaxer.php` دقیقاً کدام endpointهای ۹۰۹۰ را صدا می‌زنند.

**آنچه از Kama برمی‌داریم (فاز IPTV):** الگوی احراز مهمان (اتاق+کدملی)، ساختار
دسته‌بندی کانال و سبد خرید خدمات. **آنچه برنمی‌داریم:** بک‌اند ASP.NET و ساختار
Apache/PHP قدیمی — این‌ها با استک ما (PHP 8.3 + nginx) هم‌خوان نیستند و فقط مرجع‌اند.
